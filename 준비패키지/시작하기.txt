1. 이번에 정한 1차 개발 범위
자동차 부품 염욕 열처리 설비 1대의 작업별 불량 위험을 예측한다.
KAMP 원본의 작업번호(배정번호)를 예측 단위로 사용한다.
공정 요약 파일 업로드 → 항목 연결 → 위험 작업 목록 → 작업 상세 공정편차가 시연 흐름이다.
Python / FastAPI / React / SQLite로 구성하며 현재 데이터·모델·API·저장을 실행했다.
React 화면은 다음 구현 단계이다. 현재 API 호출 화면은 /docs 에서 제공된다.

원본에는 경도 측정값이 없으므로 강구 경도 예측과 혼합하지 않는다.
먼저 준비한 강구 경도 합성데이터와 모델은 별도 기능시험·확장안으로 보관했다.
현재의 기본 실행 명령은 app_kamp:app이다. app:app은 이전 강구 합성 시연이다.

2. 확보한 원본과 가공 결과
원본 보관 위치(현재 프로젝트):
참고자료/KAMP_열처리_품질보증/
  Dataset_열처리 품질보증 AI 데이터셋.zip : 222,711,829 bytes
  Guidebook_열처리 품질보증 AI 데이터셋.pdf : 75쪽, 개인 다운로드 정보가 표시된 사본
  원본/data/data.csv : 2,939,722행 × 21열, CP949 인코딩
  원본/data/열처리_품질데이터.xlsx : 136행 × 7열
  원본/data/train.csv, 데이터설명.txt
ZIP의 품질전처리후데이터.csv는 보존되어 있으며 중복 대용량 파일은 따로 풀지 않았다.

가공한 파일(본 패키지의 kamp/):
- process_batches.csv: 136작업의 입력과 식별자·시각·출처, 센서 18종 평균/표준편차 36개
- quality_batches.csv: 작업별 양품·불량·총수량과 불량률
- joined_batches.csv: 작업번호로 일대일 연결한 분석용 자료
- audit.json: 행·열 수, 결측 개수, 연결 검증, 원본 SHA-256
- split_manifest.csv: 학습/검증/최종 평가 작업번호와 정답
- validation_comparison.csv, benchmark.json: 모델 3종의 비교와 최종 평가
- holdout_predictions.csv: 최종 평가 36작업의 예측과 정답
- demo_upload.csv: 예측용 20작업. 품질 정답을 포함하지 않음
- pilot_model.joblib: 이 프로젝트에서 학습한 시제품 모델
- verification.json: API 및 데이터 검증 11건 통과 기록

약 294만 센서 행이 294만 독립 품질 표본을 의미하지는 않는다. 품질 정답은 136작업이다.
원본의 작업번호·시간 중복은 0건이며, 모든 작업이 품질자료와 일대일 연결된다.
양품수량+불량수량=총수량을 전 작업에서 확인했다.
소입로 CP 모니터 값은 가이드북의 중복 측정 채널 설명에 따라 제외했다.
평균·표준편차는 각 작업의 관측값에서 계산했다. 전체 기간 평균으로 먼저 결측을 채우지 않는다.
모델의 결측 대체값과 표준화 계수는 학습 구간에서만 학습한다.

3. 품질 목표와 평가 방식
불량률(%) = 불량수량 / 총수량 × 100.
학습 구간의 불량률 3사분위수 0.049443144463256726% 이상을 위험(1)으로 정했다.
약 494.43 PPM에 해당하며, 상대적으로 불량률이 높은 작업을 구분하는 분석 기준이다.
기업의 승인 불량 기준이나 제품 합격/불합격 규격을 의미하지 않는다.
가이드북의 전체자료 기준 0.046% 대신 학습자료만으로 기준을 정해 이후 구간에 고정 적용했다.

학습: 2022년 1~4월 78작업(위험 20)
검증: 2022년 5월 22작업(위험 4)
최종 평가: 2022년 6~7월 36작업(위험 7)
작업의 센서 시작~종료 구간도 서로 겹치지 않는 것을 확인했다.
검증 F2(재현율을 더 중시)와 정밀도로 모델·알림 임계값을 선택했다.
학습 모델 3종: 로지스틱 회귀, 랜덤포레스트, XGBoost.
선택된 시제품: 로지스틱 회귀, 알림 점수 임계값 0.55.

검증 성능:
로지스틱 회귀: 재현율 75.0%, 정밀도 37.5%, F2 0.625
랜덤포레스트: 재현율 100%, 정밀도 21.1%, F2 0.571
XGBoost: 재현율 100%, 정밀도 23.5%, F2 0.606

선택 완료 후 최종 평가를 한 번 실행했다:
위험 7건 중 2건 발견, 미탐 5건, 오탐 9건, 정상 20건 정확 분류.
재현율 28.6%, 정밀도 18.2%, F1 0.222, F2 0.256, ROC AUC 0.448.
모든 작업을 위험으로 처리하는 기준모델의 F2는 0.547이다.
따라서 현재 모델은 현장 활용 성능을 입증하지 못했다.
이는 데이터 확보·연결·모델 비교가 실행되었다는 시제품 결과이며, 성능 달성 결과가 아니다.

개선 우선순위:
- 불량 유형·재질·제품 조건을 멘토와 검토하고 목표를 실제 현장 기준에 맞춘다.
- 학습/검증 기간에서 시간순 교차검증과 제한된 변수 선택을 검토한다.
- 시간별 조건 차이와 표본 부족을 분석한다.
- 최종 평가를 본 뒤 수정한 모델의 동일 자료 재평가는 개발 참고값으로 구분한다.
  현장 성능 주장은 새 기간 또는 새 기업 데이터로 추가 검증한 후 한다.
- 현재 입력은 작업 전체 요약이다. 공정 중 조기예측으로 설명하려면 예측 시점 이전의
  센서 구간만 재구성하고, 검사 시각·공정 이력과 정렬해야 한다.

4. 실행과 재현
다른 PC에서 Python 3.12를 설치한 뒤 패키지 폴더에서 실행한다.
  python -m venv .venv
  .venv\Scripts\python -m pip install -r requirements.txt
  .venv\Scripts\python train_kamp.py
  .venv\Scripts\python verify_kamp.py
  .venv\Scripts\python -m uvicorn app_kamp:app --host 127.0.0.1 --port 8765
브라우저: http://127.0.0.1:8765/docs

현재 PC에서는 run_local.ps1을 사용한다.
원본에서 다시 가공하려면 다음을 실행한다.
  python prepare_kamp.py --source "원본 data.csv와 열처리_품질데이터.xlsx가 있는 폴더"
이 명령은 공정 파일을 분할해서 읽어 작업별 통계량을 계산한다.
모델 3종을 다시 비교하려면 train_kamp.py를 실행한다.
실행 순서: prepare_kamp.py → train_kamp.py → verify_kamp.py.
동봉 CSV를 그대로 사용할 때는 prepare_kamp.py를 생략할 수 있다.

API:
GET /health, /schema, /model
POST /preview: CSV·Excel의 컬럼·행 수 확인
POST /predict: file과 mapping(JSON)으로 예측. 예: {"배정번호":"batch_id"}
GET /runs/{run_id}: SQLite에 저장한 실행 결과 조회

입력: UTF-8 CSV 또는 xlsx 첫 시트, 10MB·10,000행 이내의 작업별 요약 파일.
540MB 원시 센서 파일은 prepare_kamp.py에서 먼저 요약한다.
필수 입력은 /schema의 batch_id, 공정 시작·종료 시각, data_source와 36개 요약값이다.
data_source는 KAMP_heat_quality_60이어야 한다.
KAMP과 다른 공정의 데이터를 사용하려면 데이터 정의와 모델을 다시 검토한다.
3개까지의 요약값 결측은 학습 중앙값으로 대체하고 표시하며, 그 이상은 보류한다.
품질 정답을 입력으로 매핑하면 차단한다. 중복 작업·문자형 센서값 등은 행별로 보류한다.
위험 점수는 보정된 실제 불량확률이 아니다.
학습 5~95백분위에서 벗어난 공정값은 참고 편차이며 안전 운전 범위가 아니다.
신뢰된 로컬 모델만 읽는다. 외부 모델 업로드 기능은 없다.

6. 기존 강구 합성 시연
data/와 models/, results/, generate_data.py, train_models.py, app.py는
앞서 준비한 100Cr6 강구 경도 합성 시연이다. 자세한 설명은 강구_합성데모_설명.txt를 본다.
합성 1,000 LOT·가상 경도검사 5,000건과 실측 KAMP 136작업의 성능은 별개다.
합성 XGBoost의 높은 수치를 KAMP 실측 성능으로 인용하지 않는다.
준비패키지/kamp/가 현재 1차 MVP의 주 분석 대상이다.

개발 시작 ZIP에는 대용량 원본과 개인화된 가이드북을 넣지 않았다.
