### GitHub Push 후 새 Clone 확인

기능 반영 커밋 `c0bed7354071396dea7c9750a1441c31f4995f5a`를 GitHub에서 별도 폴더에 실제 Clone했다. 154개 Git 파일 내용이 로컬 커밋과 일치하고 기존 `871248f`가 조상으로 보존된 것을 확인했다. 저장소는 Private이며 강제 Push나 이력 재작성은 수행하지 않았다.

새 가상환경의 `setup.ps1` 설치, API12개, 실제 서버 재시작 테스트가 모두 통과했다. `start.ps1 -Port 8772`로 실행한 브라우저에서도 합성120행 불러오기·40필수 연결·검증·추론·저장이 동작했고 콘솔 오류는0개였다. 예측120행/오류0행/평균점수0.479는 합성 기능 시험이며 성능 측정값이 아니다.

[Clone 검증 기록](verification/repository/remote_clone/clone_results.json), [API](verification/repository/remote_clone/api_results.json), [재시작](verification/repository/remote_clone/restart_results.json), [실제 화면](verification/repository/remote_clone/dashboard.png)에 증거를 보존했다. 같은 Windows PC의 별도 Clone·새 환경에서 검증했으며 물리적으로 다른 PC까지 시험한 것은 아니다. 이 기록을 추가하는 후속 커밋은 문서·증거만 변경하며 실행 코드는 동일하다.

## 성능 검증의 판정

KAMP최고CV후보의 검증 AP0.2290, F20.3846는 기존 AP0.3770, F20.6061보다 낮다. 적용 조건을 통과하지 못해 기존 RandomForest와 경계0.35를 유지했다. SECOM은 별도 시간 보류에서 AP0.0889, Recall4.3%로 실용 성능을 확보하지 못했다.

테스트 통과는 기능과 기록 보존을 확인한 결과다. 모델의 품질판정 신뢰성이나 공장 일반화 성능을 입증하지 않는다. 현재 앱은 기술검증용 MVP다.

## 보존 및 미검증 범위

기존 원본·현재/초기모델·기존평가 JSON/CSV·SQLite이력을 덮어쓰지 않았다. 보고서는 개선 전 사본을 저장한 뒤 갱신했다. 기존 데이터베이스 해시도 동일하다. API형식·모델버전·화면 동작은 그대로이므로 기존 이력 재점수화나 모델 복구 작업이 발생하지 않았다.

신규 열처리 기업/기간자료, 실제 검사시각 기준 온라인 예측, 제품·설비별 그룹 독립성, 현장 사용자 비용·검토량, 실제 불량 감소 효과는 검증하지 못했다. SECOM의 보류도 동일 출처의 과거 시간 구간이며 타기업 외부 검증이 아니다.

실행 명령과 환경 제약은 [실험 안내](../experiments/quality_20261101/README.md)에 있다. 새 회귀 증거는 `ICT_EVIDENCE_DIR`로 별도 경로를 지정해 남길 수 있다.
