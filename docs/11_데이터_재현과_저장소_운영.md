# 데이터 재현과 저장소 운영

일반 실행은 원본 다운로드와 재학습 없이 `scripts/setup.ps1` → `scripts/start.ps1`로 가능하다. 이 문서는 연구를 다시 수행하거나 팀 저장소를 관리할 때의 절차다.

## 배포본과 로컬 연구 환경

배포본에는 현재 RF 모델, `benchmark_public.json`, 독립 난수 합성 예제가 있다. 개별 KAMP 작업의 센서·품질 행과 기존 분포 재표집 합성파일은 없다. `quality_service.py`는 로컬 원래 benchmark/예제가 있으면 사용하고, 없으면 공유용 파일을 읽는다. 예측 모델·경고0.35·36특성 입력은 동일하다.

관계 차트는 배포본에서 최소5작업 구간 평균으로 표시한다. 원래 로컬 benchmark를 가진 연구 환경은 기존 개별 학습자료 차트를 유지한다. 실측 예제 부재를 합성 실측으로 위장하지 않는다. `/sample?kind=real`은 원본이 없으면404안내, `/schema`의 sample_availability는 제공 가능 여부를 알린다. 실측 업로드 API 자체는 그대로 사용할 수 있다.

## KAMP 학습 재현

1. [공식 자료60](https://www.kamp-ai.kr/aidataDetail?DATASET_SEQ=60)에서 계정·이용조건에 따라 원본을 직접 확보한다. 개인화 가이드북은 Git에 올리지 않는다.
2. `data.csv`와 `열처리_품질데이터.xlsx`를 `참고자료/KAMP_열처리_품질보증/원본/data/`에 둔다. 기본 경로는 코드에 상대경로로 정의되어 있다.
3. 기존 로컬 결과가 없는 **별도 Clone**에서 아래 순서로 실행한다. 기존 작업환경의 결과를 덮어쓰는 용도로 사용하지 않는다.

```powershell
.\.venv\Scripts\python.exe 준비패키지\prepare_kamp.py
.\.venv\Scripts\python.exe 준비패키지\train_kamp.py
.\.venv\Scripts\python.exe 준비패키지\train_release.py
.\.venv\Scripts\python.exe experiments\quality_20261101\prepare.py --temporal
.\.venv\Scripts\python.exe experiments\quality_20261101\train.py --dataset kamp --run kamp_reproduction_01
```

`prepare_kamp.py`가 집계 CSV를, `train_kamp.py`가 기존 시간 분할 명세를 만든다. `train_release.py`는 동봉 release를 다시 쓰므로 배포 모델의 해시를 먼저 기록하고 별도 Clone에서만 실행한다. 새 실험은 존재하지 않는 run 이름을 요구한다. 원본·가공자료·새 실험파일은 재공유 전에 라이선스와 행별 정보 포함 여부를 검토한다.

기존 KAMP 보류36작업은 이미 본 개발자료다. 재현 명령을 반복해도 새로운 독립 검증이 추가되지 않으며, 그 점수를 보고 다시 튜닝하지 않는다. 원본 검증 스크립트와 초기 실험 보존본 검증은 배포에서 제외한 로컬 파일을 요구한다.

## SECOM 재현

```powershell
.\.venv\Scripts\python.exe experiments\quality_20261101\download_secom.py
.\.venv\Scripts\python.exe experiments\quality_20261101\train.py --dataset secom --run secom_reproduction_01
```

공식 UCI 원본 약1.9MB를 다운로드하며 SHA256이 기록 버전과 다른 경우 중단한다. 기존 출처 기록은 보존한다. CC BY4.0 인용과 변경사항은 [데이터 공유 정책](../DATA_USAGE.md)에 있다. SECOM 재현은 반도체 사례이며 열처리 모델 검증이 아니다.

## 회귀 테스트

```powershell
$env:ICT_EVIDENCE_DIR = "$PWD/tmp/current-test-evidence"
powershell -ExecutionPolicy Bypass -File .\scripts\test.ps1
.\.venv\Scripts\python.exe tests\verify_restart.py
Remove-Item Env:ICT_EVIDENCE_DIR
```

API12개는 동봉 합성 fixture를 사용하며 원본 데이터가 필요 없다. 프로세스 재시작 테스트는 임시 DB와8767포트를 사용하고 자신이 시작한 서버를 종료한다. 기본 테스트 결과 경로는 `tmp/test-evidence/`다. 검토를 마친 기록만 docs로 복사한다.

브라우저 자동 회귀(개발 의존성·Edge 필요):

```powershell
# 터미널1
$env:ICT_DB_PATH = "$PWD/tmp/browser-test.sqlite3"
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Port 8766
# 터미널2
$env:ICT_EVIDENCE_DIR = "$PWD/tmp/browser-evidence"
node frontend/tests/e2e.mjs
```

일반 실행으로 돌아가기 전 `Remove-Item Env:ICT_DB_PATH -ErrorAction SilentlyContinue`를 사용한다. 테스트 DB를 개인 작업 DB와 혼동하지 않는다.

## 커밋 전 검토

변경 파일을 명시적으로 stage하고 `python scripts/audit_repository.py --staged`와 `git diff --cached --check`를 실행한다. `.gitignore`는 이미 추적된 파일을 자동 해제하지 않으므로 추적 파일 목록도 확인한다. Private설정과 일반 Push를 유지한다. 초기 커밋의 면담 문서·가공 CSV는 현재 트리에서만 제외했으며 과거 이력은 남아 있다.

`scripts/package_release.py`는 Git추적 파일을 기준으로 패키징한다. ignored원본이 로컬에 있어도 포함하지 않는다. 과거 v1.0/성능개선 ZIP은 로컬 기록으로 보존하며 최신 공유 기준은 GitHub main이다.

기술문서는 현재 저장소 구조를 기준으로 관리한다. 이전 실험의 `report.py`는 개인 보존본이 필요하며 재생성 결과를 `tmp/generated_reports/`에 쓴다. README와 최신 docs를 자동으로 덮어쓰지 않는다.
