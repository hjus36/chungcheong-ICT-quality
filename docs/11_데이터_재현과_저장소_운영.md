# 데이터 재현과 저장소 운영

일반 실행은 원본 없이 `scripts/setup.ps1` → `scripts/start.ps1`로 가능하다. 이 문서는 모델을 다시 만들거나 저장소를 관리할 때의 절차다.

## 1. 학습 환경

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -Train
```

서비스와 같은 고정 버전(`준비패키지/requirements-lock.txt`) 위에 `ml_workflow/requirements-train.txt`(pyyaml, pyarrow, matplotlib)를 더 설치한다. **scikit-learn 버전이 바뀌면 같은 seed라도 fold 배정이 달라진다.** 반복 CV로 영향을 줄였지만, 결과를 비교할 때는 lock 버전을 쓴다.

원본은 [ml_workflow/data/README.md](../ml_workflow/data/README.md)대로 받아 `ml_workflow\data\`에 두고 SHA-256을 확인한다. 다른 위치면 `ICT_DATA_PATH`.

## 2. 학습 → 승격 → 서비스 반영

```powershell
.\scripts\train.ps1 -Run im_v3              # 실행 (runs\im_v3\)
.\scripts\train.ps1 -Run im_v3 -Resume      # 끊겼을 때 이어서
# runs\im_v3\report.md 검토 (서비스 배포 후보 표의 승격 조건)
.\scripts\train.ps1 -Run im_v3 -Resume -Stages report -Promote
.\scripts\test.ps1
.\scripts\start.ps1                          # 재시작하면 새 모델 적용
```

| 규칙 | 이유 |
|---|---|
| 실행 이름이 이미 있으면 거부 | 결과 덮어쓰기 방지 |
| `--resume`은 설정·코드·데이터 해시가 같을 때만, 끝난 단계는 다시 못 돌림 | 서로 다른 조건의 결과가 섞이지 않게 |
| 승격 조건 미통과면 `promote.py` 중단 | Gate 1·2, holdout Recall ≥ 0.9, 기준선보다 나은 모델만 서비스 반영 |
| 이전 release는 `준비패키지/release/previous/`에 보관 (git 제외) | 되돌리기 |
| `release_info.json`에 실행 이름·해시·버전 기록, `verify_data.py`가 확인 | 서비스 파일이 승격 없이 바뀌었는지 탐지 |
| 승격 후 `make_synthetic.py` | 합성 예제가 새 모델의 특징·범위를 따르게 |

holdout은 같은 분할을 쓰는 한 이미 본 자료다. 실행 결과는 '개발 참고 평가'로 표기된다(`experiment.yaml`의 `evaluation.holdout_status`). 이 점수를 보고 규칙을 다시 고치지 않는다. 새 실험일 자료가 생기면 규칙을 고정하고 그 자료로 평가한다.

## 3. 데이터셋을 바꿀 때

[WORKFLOW.md 6장](../ml_workflow/WORKFLOW.md#dataset-change) 절차를 따른다. 핵심: `--stages validate`로 미분류 컬럼 확인 → `columns.yaml`의 측정 단계·서비스 메타·단위 규칙 작성 → 전체 실행 → 승격. 서비스 코드와 화면은 고치지 않는다.

## 4. 테스트

| 명령 | 내용 |
|---|---|
| `scripts\test.ps1` | 릴리스 무결성, API, 공개 모드, 서버 재시작 |
| `scripts\test.ps1 -Workflow` | + 워크플로우 종단 테스트 (작은 합성 데이터, 원본 불필요) |
| `scripts\test.ps1 -Browser` | + 브라우저 (Edge, 서버를 8766에 따로 실행). 다른 브라우저는 `ICT_BROWSER_PATH` |

## 5. 프런트 수정

`scripts\setup.ps1 -RebuildFrontend` 또는 `frontend`에서 `pnpm install`, `pnpm build`. `frontend/dist`도 커밋한다(배포가 빌드 결과를 그대로 쓴다).

## 6. 공유 전 점검

```powershell
git add -A
.\.venv\Scripts\python.exe scripts\audit_repository.py --staged
```

원본(`ml_workflow/data/*`), 실행 결과(`ml_workflow/runs/`), parquet, 승격되지 않은 모델, 행 단위 파일, `준비패키지/local/`, 개인 경로·인증정보 패턴, 깨진 Markdown 링크를 검사한다.
