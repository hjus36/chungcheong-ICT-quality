# 개발 현황 및 후속 계획

기준일 2026-11-01. 팀 가용시간은 1인 주 6~8시간, 팀 전체 주 24~32시간을 계획 기준으로 한다. 아래 일정은 내부 계획이며 주관기관 확정 일정이 아니다.

## 완료한 개발

| 영역 | 현재 상태 | 확인 자료 |
|---|---|---|
| 데이터 처리 | 열처리 센서 2,939,722행과 품질 136작업 연결, 36입력 정의 | 문서03·10, 데이터 사전 |
| 웹 MVP | React/FastAPI 업로드·매핑·검증·분석·상세·이력·CSV 내보내기 | 문서02·05·08 |
| 서비스 모델 | RF와 경고 0.35 적용, 기준선·오경고·미탐 공개 | 문서06 |
| 추가 실험 | KAMP 18후보·기존 RF 대조군 및 SECOM 6후보 비교 | experiments/quality_20261101 |
| 적용 판단 | 성능 개선 근거 부족으로 기존 모델 유지 | 선정 잠금과 final_results.json |
| 기능 검증 | API·브라우저·DB 재시작 검증, 모델 점수 재현 | 문서07 |
| 팀 공유 구성 | 설치 스크립트·고정 의존성·정적 빌드·독립 합성 예제·기술문서 | README, DATA_USAGE, 문서11 |

이전 5주 계획에 있던 위 기능은 이미 구현했다. 새 기간의 기업 데이터나 현장 운영 효과를 검증한 것은 아니다. 구현 완료와 모델 실용 성능 확보를 구분한다.

## 팀의 후속 검토 순서

| 순서 | 수행 내용 | 완료 기준 |
|---|---|---|
| 1주차 | 팀원 Clone·합성 시연·코드 및 데이터 흐름 공유 | 각자 설치·분석·이력 복원 성공, 담당 영역 합의 |
| 2주차 | 멘토·현장 담당자와 품질 기준 및 활용 시점 협의 | 실제 불량 정의·검사시각·검토량·미탐/오경고 비용 기록 |
| 3주차 | 동일 공정 새 기간 자료 확보 및 품질 감사 | 이용 권한·작업 식별자·제품/설비 구분·검사 정답 확인 |
| 4주차 이후 | 새 데이터의 시간·그룹 분할 계획을 먼저 고정한 뒤 실험 | 기존 모델·단순 기준선과 비교, 성능과 불확실성 보고 |
| 조건 충족 후 | 현장 담당자가 결과를 검토하는 제한적 시범 운영 | 운영 기준·권한·백업·복구와 효과 측정 계획 합의 |

자료가 확보되지 않으면 모델 개선 일정은 확정하지 않는다. SECOM은 별도 반도체 사례이며 열처리 학습자료를 대신하지 않는다. 같은 보류자료를 반복 평가해 현장 성능이 개선됐다고 판단하지 않는다.

## 관리 원칙

- 새 원본과 개인 분석 이력은 로컬에 보관하고 공유 권한을 먼저 확인한다.
- 현재 모델을 교체하려면 사전에 정한 적용 조건과 새 검증 근거를 충족한다.
- 학습 전처리는 학습 구간에서만 fit하며 정답 열을 추론 입력에 쓰지 않는다.
- 통계 구간을 기업 규격으로 설명하거나 위험 점수를 실제 불량 확률로 설명하지 않는다.
- 기존 기록을 덮어쓰지 않고 새 run 이름과 모델 버전으로 재현한다.

검증 범위는 [검증 결과](07_검증_결과보고서.md), 데이터 재확보와 저장소 관리는 [운영 안내](11_데이터_재현과_저장소_운영.md)에 따른다.
