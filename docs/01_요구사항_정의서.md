# 요구사항 정의서

프로젝트: 제조공정 데이터 기반 품질위험 예측 및 공정편차 분석 MVP · 무한루프팀

작성 기준: 2026-11-21 (사출성형 자료로 교체). 공식 근거는 로컬 보관 중인 공고문·과업지시서 인쇄 17~18쪽 과제 6이다. 공식 원문은 GitHub 배포본에 포함하지 않는다.

## 목적과 범위

사출 사이클 단위로 기록된 공정 데이터를 받아, 품질 담당자가 **먼저 검사할 부품**과 **학습 정상 범위를 벗어난 공정변수**를 함께 확인하게 한다.

| 항목 | 정의 |
|---|---|
| 공정 1종 | 플라스틱 사출성형 (ProBayes 실험 자료, 재료 PP·ABS) |
| 판정 대상 1종 | 부품 불량 여부 `LBL_NOK` = 싱크마크 또는 미충전이 있으면 1 |
| 예측 시점 | 사이클 종료 직후. 탈형 후 IR·카메라 측정, 냉각 후 무게, 시뮬레이션 값은 쓰지 않는다 |
| 출력 | 보정된 위험 점수(0~1), 2단계 검토 구분(우선 검토 / 통상 검토), 참고 구간 이탈 변수 |

실시간 설비 제어, 출하판정, 실제 기업 현장 효과는 구현·실증 범위가 아니다. 참고 구간(학습 정상 부품 5~95백분위)은 공정 규격이 아니다.

|---|---|
| 구현 대상 | CSV/Excel 공통양식, 품질위험 예측, 변수와 범위 분석, 웹 화면 |
| 주요 기능 | 업로드, 원천 열 매핑, 결측·이상·형식 처리, ML, 분포·품질 관계·영향변수, 대시보드 |
| MVP | 공정 1종·대상 1종, 가상자료 정의 및 생성, 단방향 처리, 3종 이상 모델 비교 후 1종 선정, 합성자료 기능검증 |
| 산출물 | 입력·합성자료 정의서, 벤치마크, 가상자료, 모델 소스, 웹 실행패키지, 기술검증 보고서, 사용자 매뉴얼 |
| 기대효과 | 예방형 관리 가능성 검증 및 실제 기업·MES 연계 기반. 현재 자료로 손실 감소를 실증하지 않는다 |

## 요구사항과 추적표

출처 O=공식 17~18쪽, U=팀 결정, P=구현 보완. 모든 Must는 기능 완료 조건이며 모델 성능 보장은 별도이다.

| ID | 우선순위·근거 | 요구사항 / 구현 | 완료 기준 / 검증 |
|---|---|---|---|
| R01 | Must O | 공정·라벨 1종 고정, 데이터 사전 | 데이터 사전이 학습 워크플로우에서 생성되고 서비스·화면과 일치 / `verify_data.py` |
| R02 | Must O | CSV UTF-8/CP949·xlsx 업로드/미리보기 | 실제 파일 열·행 표시 / API+브라우저 |
| R03 | Must O,U | 부품 ID·사이클 시각·출처·특징 매핑, 원본 데이터셋 열 이름 자동 제안 | 라벨·사후측정 열을 특징에 연결하면 거부 / API 테스트 |
| R04 | Must O,U | 결측·중복·날짜·비수치·무한값·허용 범위 검증 | 행별 이유, 필수 특징 결측은 제외, 선택 특징 결측은 학습 중앙값 대체 / API 테스트 |
| R05 | Must O,U | LR·RF·XGBoost·SVM 비교 후 1종 선택 | 반복 그룹 CV, Gate 1·2, 선택 기록표, 기준선 / 워크플로우 리포트 |
| R06 | Must O | 품질위험 예측·검토 우선순위 | 실제 모델 추론과 화면 일치 / API·E2E |
| R07 | Must O | 변수 분포·품질 관계·영향변수·참고 구간 이탈 | 집계값만 공개, 규격과 구분 / API·화면 |
| R08 | Must O | 한국어 React 대시보드 | 업로드→매핑→검증→예측→상세 / 브라우저 테스트 |
| R09 | Must U | SQLite 저장·이력 조회 | 재시작 후 동일 결과 / 재시작 테스트 |
| R10 | Must O | 합성자료 정의·기능 검증 | `synthetic.yaml`과 생성 정의, 실측과 구분, 가상 라벨 표기 / 테스트 |
| R11 | Must U,P | 제한·오류·안정성 | 10MB·1만 행(공개 500행)·100열, 형식·손상 처리 / 경계 테스트 |
| R12 | Must U | 누수 방지 | 사후측정 자동 제외, 그룹 분할, 학습 부분에서만 전처리·특징 선택·판정 기준 결정 / WORKFLOW 3장 |
| R13 | Must O,U | 재현 가능한 학습·승격 | 실행 이름·설정·코드·데이터 해시 기록, 승격 조건 통과 모델만 서비스 반영 / `promote.py` |
| R14 | Must O | 소스·실행·검증·매뉴얼·결과보고 | 문서와 실행 일치 |
| R15 | Should U | Windows 설치·실행·학습 스크립트, 정적 빌드 동봉 | `setup.ps1`, `start.ps1`, `train.ps1`, `test.ps1` |
| R16 | Should P | 결과/오류 CSV, 수식 주입 보호 | API 테스트 |
| R17 | Should P | 실제 판정(actual_label) 사후 비교 | 예측 입력에서 제외, 혼동행렬 표시 / API 테스트 |
| R18 | Could O | 실시간 조기예측·기업/MES 연계 | 후속 범위 |

사용 시나리오: 담당자가 사이클 단위 CSV를 올리고 열을 연결한다. 검증 단계에서 오류 행과 결측 대체를 확인한 뒤 분석한다. 위험 점수가 높은 부품부터 검사하고, 참고 구간을 벗어난 변수를 확인한다. 실제 판정이 있으면 예측과 비교한다. 이력에서 같은 결과를 다시 연다.

성능 목표(내부): 20행 로컬 API 추론 5초 이내. 모델 성능은 단순 기준선과 함께 보고하며, holdout 결과가 개발 참고 평가임을 표기한다. 최종 충족 상태는 문서 07·09에 기록한다.
